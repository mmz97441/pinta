- ESLint ciblé sur composants client, connexion, changement de mot de passe, suivi public, facture client et domaine : réussi.
- Recette navigateur existante : **8 scénarios réussis** ; nouvelle recette client : **12 scénarios réussis** ; reprise des messages : **3 scénarios réussis**, sur le build statique local, API interceptées. Les résultats définitifs sont enregistrés dans les fichiers indiqués ci-dessous.
- Suites historiques intégrées : préparation-client **11 contrôles réussis**, browser-regression **11 contrôles réussis** et relevé des champs. Accessibilité globale : **32 combinaisons écran / thème / viewport**, aucune violation automatique ni débordement détecté.

- Aucun appel automatique `queue_message`, aucune mutation métier réelle. Le navigateur n’a accès qu’aux fixtures ; les faux dépôts, fausses invitations et lectures sont interceptés.
- Recette finale indépendante des modifications à chaud : `PINTA_TEST_URL=http://127.0.0.1:4187`. Les résultats transitoires de développement ne sont pas retenus comme preuve de livraison.

## Décisions conditionnelles et limites

1. **Adresse de réception, instructions bancaires et échéance :** les sources parcourues ne fournissent pas de donnée vérifiée universelle. Le produit donne une action utile pour l’obtenir auprès de l’équipe. Publier une adresse/IBAN faux ou dériver automatiquement une échéance commerciale serait une régression.
2. **Telegram déjà associé :** le client voit l’association et l’aide pour la changer ; aucune déliaison silencieuse n’est introduite. Le processus de changement doit continuer à vérifier le titulaire.
3. **Brouillons :** conservation locale dans la session du navigateur, pas synchronisation entre appareils. Les pièces jointes locales ne deviennent pas des documents enregistrés avant validation du dépôt.
4. **Historique :** recherche sur tous les dossiers accessibles au client, chargement par le mécanisme paginé existant ; aucun élargissement des permissions. Les très grands historiques restent à mesurer en conditions réelles.
5. **Notifications :** les types reconnus ciblent message/document ; les autres ouvrent l’état courant de l’expédition. Marquer comme lu ne valide ni paiement, ni facture, ni accord.
6. **Accessibilité :** contrôles automatisés et viewport mobile Chromium, pas certification WCAG ni test sur appareil physique ou avec lecteur d’écran. Aucun gain de temps chiffré n’est affirmé sans étude utilisateur.
